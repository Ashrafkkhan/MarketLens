# MarketLens — Project Documentation

*From headline to decision: a quantitative GenAI research engine for Indian equities (NSE/BSE).*

---

## 1. What is MarketLens?

Every day hundreds of financial headlines hit the Indian market. A trader cannot read them all, and cannot tell which ones will actually move a stock.

MarketLens reads a news headline and answers four questions:

1. **What happened?**: company, event type, surprise, sentiment.
2. **Will the stock beat the market?**: the probability that it outperforms NIFTY 50 by more than 0.5% over the next 3 trading days.
3. **Has this happened before?**: how similar past events actually turned out.
4. **What should I do?**: a research memo, a conversational analyst copilot and a price forecast.

Everything is explained with numbers taken from data, not guessed by an LLM.

## 2. Architecture at a glance

```
 News RSS feeds ──► PostgreSQL (companies, news, market_data, market_indices, events)
                          │
   Headline ──► [1] Event extraction  (Qwen2.5-1.5B → structured JSON)
                [2] Sentiment          (FinBERT → positive / negative / neutral)
                [3] Technical features (momentum, volatility, volume anomaly from DB)
                [4] Model C            (21 features → P(AR3 > +0.5%))
                [5] Historical memory  (FAISS + MiniLM → win rate, median AR3, analogs)
                [6] Memo synthesis     (LLM → 4-section research memo)
                          │
                    FastAPI  /api/v1  ──►  Next.js frontend
                                            ├─ Live event feed
                                            ├─ Analysis cockpit (tabs)
                                            └─ Analyst chat copilot
```

| Layer | Technology |
|---|---|
| Backend | FastAPI, SQLAlchemy, Alembic, PostgreSQL |
| NLP | Qwen2.5-1.5B-Instruct (extraction), ProsusAI/FinBERT (sentiment) |
| ML | scikit-learn / XGBoost pipeline ("Model C"), joblib artifact |
| Vector memory | FAISS `IndexFlatIP`, `all-MiniLM-L6-v2`, Parquet metadata |
| Price forecast | Random Forest / XGBoost / LSTM bridged from `ml_genai/stock-price-prediction-ml` |
| Chat LLM | Groq (`openai/gpt-oss-20b`) → Gemini → Ollama → local Qwen → deterministic fallback |
| Frontend | Next.js, React, Tailwind |

## 3. How it works, step by step

### 3.1 Data foundation
- `scripts/collect_news.py` ingests financial news via RSS; `collect_market_data.py` and `collect_indices.py` pull daily OHLCV for stocks and the NIFTY 50 benchmark (`^NSEI`) using yfinance.
- Tables: `companies`, `news`, `market_data`, `market_indices`, `events`. Migrations are managed with Alembic.

### 3.2 Event intelligence (`backend/services/event_extractor.py`)
- A local **Qwen2.5-1.5B-Instruct** model turns the headline into structured JSON: `ticker`, `event_type`, `surprise` (BEAT / MISS / IN_LINE), `magnitude`, `sentiment`, `summary`.
- If the JSON fails to parse after retries, a **rule-based regex extractor** takes over, so the pipeline never fails.
- The ticker is checked against the companies table so it cannot break foreign keys.
- **FinBERT** returns continuous probabilities (positive / negative / neutral) rather than a single label.

### 3.3 Technical alignment (`finalpipeline.compute_technicals_from_db`)
From the last ~35 trading days of the ticker and NIFTY 50 it computes: 5-day and 20-day momentum, 20-day realised volatility, volume anomaly (today's volume ÷ 20-day mean) and NIFTY 5-day return.

### 3.4 Model C: the predictor (`backend/ml/`)
- Target: **AR3 > +0.5%**, meaning the stock's 3-day return minus NIFTY 50's 3-day return.
- Inputs: 21 features: 5 technicals, 3 FinBERT scores, one-hot event type, one-hot surprise and magnitude.
- **Chronological train/validation/test split** so the model never sees the future.
- Output: probability, a signal (1 = outperform, 0 = underperform) and a conviction label (HIGH CONVICTION BULLISH … HIGH CONVICTION BEARISH).
- Training and comparison: `scripts/run_phase3_training.py`, `notebooks/03_model_comparison.ipynb`.

### 3.5 Historical evidence engine (`backend/memory/`)
- Every past event is embedded as `"[{ticker}] {event_type} | Surprise: {surprise} | {summary}"` with MiniLM and stored in a FAISS cosine-similarity index.
- For a new headline it retrieves the nearest past events and reports: **win rate**, **median AR3**, mean, standard deviation, **max gain / max loss** and the **top analogs** with their real outcomes.
- This gives every prediction a sanity check from real history: *"in 20 similar situations, the stock outperformed X% of the time."*

### 3.6 Research memo (`backend/intelligence/synthesizer.py`)
A four-section memo: executive thesis, technical/event drivers, historical precedent, downside risks and invalidation. It is generated by an LLM and falls back to a deterministic template (zero hallucination, always available).

### 3.7 Analyst copilot (`POST /api/v1/chat`)
- The frontend sends the conversation plus the active analysis.
- The backend builds a system prompt containing the headline, extracted event, Model C probability, FAISS evidence and (when asked about price) a live forecast.
- LLM cascade, first success wins: **Groq → Gemini → Ollama → local Qwen → deterministic template**. This gives a fast answer normally and keeps working offline.
- Rules: answer only from the supplied numbers; never invent targets.

### 3.8 Price forecast (`POST /api/v1/price-forecast`)
- RF / XGBoost / LSTM models predict 7 trading days of price.
- If a ticker has no trained model, training starts in the background and the user is told to ask again shortly.

## 4. API reference (`/api/v1`)

| Method | Path | Purpose |
|---|---|---|
| POST | `/analyze` | Full pipeline: extraction → technicals → Model C → FAISS → memo |
| POST | `/predict` | Model C inference only |
| POST | `/evidence` | Historical analog search only |
| GET | `/events` | Recent extracted events for the live feed |
| POST | `/price-forecast` | 7-day price forecast for a ticker |
| POST | `/chat` | Grounded analyst copilot |
| GET | `/health` | Component status (Model C, FAISS, LLMs, DB) |

Swagger UI: `http://localhost:8000/docs`

## 5. Frontend

- **Live Event Feed**: latest extracted events from the database, plus "+ Analyze" for any custom headline.
- **Analysis Cockpit**: tabs for Overview (probability, signal, sentiment), Technicals, Evidence (win rate, analogs), Memo and Features.
- **Analyst Chat**: suggestion chips, forecast cards and a "Grounded via {model}" footer so you always see which model answered.

## 6. Setup and run

```bash
# backend
python -m venv venv && .\venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env          # set DB credentials, GROQ_API_KEY, optional GEMINI_API_KEY
alembic upgrade head
python scripts/build_vector_index.py
uvicorn backend.main:app --port 8000 --reload

# frontend
cd frontend && npm install && npm run dev
```

Environment keys: `GROQ_API_KEY`, `GROQ_MODEL` (default `openai/gpt-oss-20b`), `GEMINI_API_KEY`, `OLLAMA_BASE_URL`, DB settings.

## 7. Known limitations (be upfront about these)

- The `/analyze` call is slow when LLM steps run on a CPU with local Qwen. Moving extraction and memo to Groq cuts this from minutes to seconds.
- Analysis results live in the browser only; they are not persisted or fed back into training.
- The news-based signal (3-day, relative to NIFTY) and the price forecast (7-day, absolute) are independent models and can disagree. They are different questions.
- Only RELIANCE has a multi-day price-forecast backtest, and the forecast does not beat a naive "tomorrow = today" baseline there. Treat forecasts as a directional hint.
- This is a research tool, not investment advice.

### Speaker 1: Hook (0:00–0:50)
> "Imagine it's 9:15 a.m. A headline drops: *Infosys shares slip amid IT sector headwinds.* You have seconds to decide. Do you sell? Hold? Is this noise, or the start of a fall?
>
> Indian retail investors face hundreds of headlines a day. Existing tools either dump raw news on you or give you a black-box 'buy' with no reasoning. Neither helps you decide.
>
> We built **MarketLens**: it reads a headline, tells you the probability that the stock will beat the market over the next three days, and shows you the real historical evidence behind it. From headline to decision, in seconds."

### Speaker 2: How it works (0:50–2:00)
*Show the architecture diagram.*
> "MarketLens is a six-step pipeline.
>
> **One**: a local language model reads the headline and extracts the company, event type and whether it was a surprise. **Two**: FinBERT, a finance-specific model, scores the sentiment, and for Infosys it found 97% negative.
>
> **Three**: we pull the stock's recent momentum, volatility and volume from our database. **Four**: our trained machine learning model, which we call Model C, takes 21 features and predicts the probability that the stock beats NIFTY 50 by more than half a percent over three days. We trained it with a strict chronological split, so it never sees the future.
>
> **Five** is what makes us different: a FAISS vector memory finds similar past events and tells you how they actually played out, with real win rates and real returns. **Six**: all of it is turned into a research memo and an analyst chat."

*Backup: if the live demo fails, play a 30-second screen recording.*

### Speaker 4: Why we win (3:40–4:30)
> "Three things set MarketLens apart.
>
> **Evidence, not opinion.** Every prediction is backed by retrieved history. We cut hallucination by design: the copilot is only allowed to use the numbers it is given.
>
> **Resilient and cheap to run.** A tiered fallback means the system works with fast cloud AI, and degrades gracefully to local models and then to a deterministic engine when offline. It always answers.
>
> **Honest about uncertainty.** We separate the news signal from the price forecast, we use a leak-free chronological split, and we publish our limitations. In finance, trust matters more than a flashy number.
>
> The market is huge: over 100 million demat accounts in India and almost no accessible, explainable research tooling for retail investors."
